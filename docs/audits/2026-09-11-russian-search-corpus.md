# Русскоязычный поиск: корпус и результаты

Дата: 2026-09-11. Исходная версия нормализации: checkout
`8364bce19912a9b7bb413d0d2a6d6c4124e81844`; исправления полноты Task-поиска и ID
предыдущего этапа уже присутствовали. Корпус зафиксирован до изменения словоформ.

## Метод

Версионируемый корпус находится в
[`tests/test_search_russian_relevance.py`](../../tests/test_search_russian_relevance.py).
Фиксированные `_RELEVANCE_CASES` содержат 13 положительных запросов к настоящим
SQLite/FTS/Structural Index fixtures. Проверяется первый результат и попадание в первые пять,
а не наличие вычисленного stem. Отдельно проверяются шесть отрицательных запросов и пять
контролей точного поиска. Последующие regression tests не меняют этот baseline.

Task создаются и завершаются через domain lifecycle. В fixture есть русские названия задач,
документы, Python-функции с русскими и английскими пояснениями и конкурирующий «Задачник».
Ожидаемые результаты заданы заранее. Это небольшой synthetic корпус по жалобе из аудита,
а не оценка произвольных проектов или запуск слабой модели.

Отрицательный корпус содержит «Монитор» и «Провернуть», но не мониторинг или проверку.
Запросы `мониторингом` и `проверкой` остаются пустыми во всех трёх областях.
Точные контроли: имя файла, две русские цитаты, регистр идентификатора и Task ID.

Дополнительные regressions проверяют приоритет точного названия над падежным совпадением,
отсутствие phrase-equivalence для `операция/опера`, `приложение/приложить` и
`подписание/подписать`, сохранение прежних fallback-словоформ, а также согласованность
`-его`/`-ией` между FTS, ranking и текущими строками evidence. Отдельный существующий
real stdio MCP scenario проверяет `задачей` для Knowledge и Task checkpoint при наличии
таких же русских слов в другом Project.

Повтор regression corpus и MCP:

```bash
scripts/dev pytest -q tests/test_search_russian_relevance.py tests/test_search.py tests/test_mcp_project_intelligence.py
```

## Границы результата

Расширяется только ограниченный набор окончаний: минимум пять символов основы,
не более одного дополнительного префикса на термин. Это не полноценный морфологический
анализатор. Короткие основы и чередования не исправлены; например, прежнее совпадение
`данные → данных` не доказывает обратное `данных → данные`.

Падежное совпадение названия имеет отдельный приоритет ниже точной фразы. Широкий
лексический префикс всё ещё может вернуть «Задачник» по `задачей`, но ниже совпавшего
названия «Управление задачами». Устранение всех семантически нерелевантных совпадений
этот корпус не доказывает.

Запрос «где реализован поиск по проекту» к английским идентификаторам остаётся межъязыковой
задачей: склонение не превращает `поиск` в `search`. Этот этап улучшает русские тексты и
смешанные запросы с явным идентификатором. Для обоснованного изменения межъязыкового поиска
нужен отдельный корпус реальных вопросов и ожидаемых мест реализации.

Контрольный read-only прогон на самом Harness с текущим кодом и отдельной временной SQLite
подтвердил ограничение (`scope=code`, `limit=5`):

| Запрос | Фактическая выдача |
| --- | --- |
| `где реализован project_search` | `scripts/eval_search_behavior.py`, `daemon.py`, `ipc.py`, `mcp_bridge.py`, `retrieval.py` |
| `where project search is implemented` | Та же последовательность; `retrieval.py` на пятом месте |
| `где реализован поиск по проекту` | `dashboard_i18n.py`, `tests/test_dashboard.py`, `tests/test_project_retrieval.py`, `tests/test_dashboard_navigation_realtime.py`; реализации поиска нет |

Это не сравнение качества произвольных репозиториев. Даже запрос с явным идентификатором
ещё требует улучшения порядка результатов: нахождение реализации на пятом месте
не означает, что поиск выбирает лучшее место первым. Регистрация и scan этого прогона
работали только с временной БД; host/skill reconciliation не выполнялся.

Исходные JSON измерений сохранены в сессии в `/tmp/harness-russian-search-baseline.json`
и `/tmp/harness-russian-search-after.json`; `/tmp` не является долговременным хранилищем.
Фиксированный корпус, критерии и результаты выше сохранены в репозитории.
