# Аудит навигации и рабочего фокуса оператора

Дата: 2026-09-23. Harness Task: `5b86dec5942b4dcba464d71f01d99080`.
Решение: [ADR-0070](../decisions/0070-project-navigation-and-operator-focus.md).

## Цель и способ проверки

Проверены все существующие типы экранов dashboard и личного хранилища: главная,
обзор проекта, задачи папки, карточка задачи, поиск, история, заметки, просмотр и
редактирование записи, настройки проекта и хранилища, первый запуск и ошибки перехода.
Исходные экраны сняты до изменений; повторный обход выполнен после реализации.
Использованы отдельные временные SQLite, Git-репозиторий и хранилище с вымышленными
записями. Реальные секреты и пользовательское состояние не использовались.

## Фокус оператора

| Ситуация | Главный вопрос | Порядок информации и действий |
| --- | --- | --- |
| Начало рабочего дня | Где нужно моё внимание? | Проекты, число задач на проверке, текущая задача и следующий шаг |
| Работа в проекте | Что происходит и куда перейти? | Постоянные разделы проекта, папки и их текущие задачи |
| Приёмка задачи | Что сделано и чем проверено? | Результат, проверки, решение оператора, затем история |
| Поиск контекста | Где моя заметка или доступ? | Один переход из задачи, фильтры/поиск записей, точный возврат |
| Редактирование заметки | Как сосредоточиться и сохранить текст? | На узком экране отдельный редактор; защита незавершённого ввода |
| Обслуживание проекта | Где изменить редкие настройки? | Отдельная вкладка с режимом, областями разработки, папками и удалением |

## Найденные проблемы и исправления

| Приоритет | Наблюдение | Исправление |
| --- | --- | --- |
| P1 | На списке и карточке задач отсутствовали разделы проекта; переход в заметки требовал обходного пути | Общая навигация «Обзор / Задачи / Заметки и доступы / Настройки» на всех экранах проекта |
| P1 | Подпись проекта в навигации вела в папку; заметки теряли исходную задачу и могли вернуть в другую папку | Правильные breadcrumbs, явный переключатель папок и «Вернуться к задаче» с проверкой принадлежности контекста |
| P1 | При уходе с форм можно было потерять незавершённое замечание | Предупреждение при уходе с изменённых POST-полей или во время сохранения; поиск его не вызывает |
| P2 | Управление скиллами, режимом и удалением конкурировало с ежедневной работой | Редкие действия перенесены в настройки; текущая задача поднята перед поиском и историей |
| P2 | Карточка показывала второстепенные формы постоянно; на узком экране действия шли после всей истории | Состояние, деплой и технические данные свёрнуты; результат и действия предшествуют истории, добавлены якоря |
| P2 | В узком хранилище список занимал пространство над записью и редактором | Отдельные состояния списка, просмотра и редактирования; явный возврат, фокус на записи/поиске, защита черновика |
| P2 | Пустая главная показывала нулевые счётчики и поиск раньше инструкции начала работы | Компактное пустое состояние с инструкцией регистрации проекта и входом в хранилище |
| P2 | Ошибки маршрута оставляли пустой экран | Понятное сообщение и ссылки к проектам и личному хранилищу |
| P2 | У мобильного меню не было доступного названия, вторичный текст и длинные строки мешали чтению | Явное accessible name, более контрастный вторичный текст, перенос длинных строк и компактные отступы |

## Проверенные маршруты

1. Главная → проект → задачи → карточка → заметки → та же карточка.
2. Настройки → обзор → задачи; breadcrumbs и боковое меню ведут в обозначенные места.
3. Две папки одного проекта: переключение и возврат из заметок сохраняют исходную папку.
4. Поиск/страницы истории → карточка; сохранение комментария обновляет ревизию и историю.
5. Хранилище: список → запись → редактор → отмена/возврат; настройки открываются и закрываются.
6. Пустой проект, первый запуск и неверная ссылка сохраняют доступные выходы.
7. Ошибки формы и устаревшая ревизия сохраняют текст и навигационный контекст.

## Сохранённые полезные свойства

Сохранены результат и следующий шаг задачи, сведения о проверках и их ревизии,
история, поиск и серверная проверка мутаций. Старые POST-маршруты проекта продолжают
работать; старый якорь `#skill-scope` ведёт к новой странице настроек. При недоступной
папке действие восстановления пути остаётся непосредственно на проблемном экране.

Хранилище остаётся на отдельном origin. Его родительская страница не выполняет
JavaScript/SSE, не читает записи и черновики. Контекст возврата проверяется сервером и
не передаётся во внутренний frame. Новое постоянное браузерное хранилище не добавлено.

## Проверки

- HTTP-регрессии: все разделы, две папки, точная задача возврата, настройки POST/303,
  старые маршруты, ошибки формы, отсутствующий и чужой контекст.
- Node выполняет production JavaScript: переход с черновиком и без него; в хранилище
  отмена выхода сохраняет редактор/текст, подтверждённый выход очищает детали без записи.
- Браузером проверены переходы, сохранение комментария, фокус и итоговая компоновка.
- Полный gate: 1384 теста, lock, Ruff, mypy (176 файлов), benchmark counters, wheel smoke.
  После финального улучшения мобильных заметок: 8 целевых тестов, повтор Ruff/mypy и
  полный pytest — **1385 passed in 346.44s**. `git diff --check` также пройден.

Первый полный прогон выявил старое ожидание расположения skill scope и таймаут
MCP-процесса в трёхсекундном окне. Ожидание обновлено на `/settings/`; wire test прошёл
отдельно и в следующем полном прогоне без изменения таймаута или реализации MCP.

## Границы доказательства

Основные dashboard-экраны проверены в настольном браузере. Узкая компоновка dashboard
проверена на production HTML/CSS во frame шириной 390 px (375 px с полосой прокрутки),
без подмены результатов на имитацию реального телефона. Хранилище дополнительно
проверено интерактивно в узкой браузерной вкладке. Горизонтального переполнения в
проверенных состояниях не обнаружено. Реальное мобильное устройство, экранный диктор
и полный WCAG-аудит не проверялись; скорость работы реального оператора не измерялась.
HTML-отчёт собран из проверенных скриншотов. Его собственная браузерная проверка
отображения остановлена двумя таймаутами автоматической проверки разрешений.

Изменения находятся в текущем checkout; пользовательская глобальная установка этим
аудитом не обновлялась. Существовавшие до задачи изменения сохранены.
